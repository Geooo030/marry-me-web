## Context

仓库当前为空，没有既有前端工程。变更目标是构建一个纯静态的移动端 H5（见 proposal.md - Why），所有嘉宾、任务和时间线数据以静态文件维护，无需后端。视觉要求"动画风"，用户已确认：首页点名字进入个人页、无打卡、无登录、瑶瑶不打开页面。

## Goals / Non-Goals

**Goals:**
- 用单一静态前端工程承载首页选人、个人行动线、全天总览三个核心视图。
- 嘉宾数据集中维护，新增或修改任务不碰页面组件。
- 移动端优先，动画活泼但低端手机也能流畅运行。
- 支持刷新后记住选择，支持分享链接直达某位嘉宾。

**Non-Goals:**
- 不做后端、数据库、登录、打卡或实时进度。
- 不做"瑶瑶无剧透模式"（用户确认瑶瑶不会打开）。
- 不做管理后台或内容编辑界面。

## Decisions

### 1. Vite + React + TypeScript

选择 Vite + React + TypeScript 搭建静态 SPA。理由：空仓库无需迁移成本，Vite 启动快、构建产物是纯静态文件，TypeScript 让嘉宾数据字段有类型约束。备选方案：Next.js（对纯静态 H5 过重）、纯 HTML/CSS（多人数据难维护）、Create React App（已不再推荐）。

### 2. Hash 路由实现深链

使用 hash 路由（`#/guest/<id>`）让每位嘉宾有可分享链接，且任意静态托管（含 VPS、对象存储、本地预览）都能工作。备选：BrowserRouter（需要服务端回退配置）和纯 state（无法分享链接）。

### 3. 单一数据文件维护内容

在 `src/data/guests.ts` 中定义嘉宾数组（id、姓名、角色标签、行动线条目），`src/data/timeline.ts` 定义全天总览节点。行动线条目字段统一为：开始/结束时间、标题、地点、详情、携带物品、注意事项、保密标记。备选：远程 JSON（需要网络请求，与"静态只读"目标冲突）。

### 4. 视觉系统：手绘任务书 + 粉金浪漫

主视觉采用暖纸底（#FDFBF7）+ 粉（#DB2777）+ 金（#A16207）+ 铅笔黑描边：贴纸卡片、手写箭头、胶带/便签装饰、轻微旋转和硬投影营造"任务书"感。标题用 ZCOOL KuaiLe（圆润中文手写感），正文 Noto Sans SC，英文点缀 Caveat。与 ui-ux-pro-max 的"Sketch Hand-Drawn + Wedding 色板"推荐一致。

### 5. 动画实现：CSS 关键帧 + Framer Motion

倒计时、浮动爱心、卡片入场用 CSS/Framer Motion，选择名字后的撒花用轻量 DOM 粒子，页面切换用 300-500ms 过渡。所有动画只动 transform/opacity，并监听 `prefers-reduced-motion` 降级。备选：GSAP（动画能力更强但体积更大，对 2-3 个页面的 H5 收益低）。

### 6. 状态与倒计时

用 `localStorage` 记住 `guestId`，刷新后直接进个人页；路由 hash 优先于 localStorage，避免分享链接失效。倒计时目标为 `2026-08-15 17:30:00+08:00`，每秒更新，超过目标时间后展示"惊喜时刻已开始"状态。

## Risks / Trade-offs

- 名单已确认："日"安心上班不参加、不进入选人名单，猪肉佬/QQ 加入，共 13 人 → 数据集中在 `guests.ts`，后续如需调整仍只需改数据文件，页面结构不受影响。
- 中文 Web 字体增加首屏网络依赖 → 字体异步加载并保留系统字体回退，正文不在关键路径上。
- 动画在低端手机上可能卡顿 → 只用 transform/opacity，限制同屏粒子数量，开启 reduced-motion 时大幅削减。
- 静态 H5 无法远程改内容 → 与"静态只读"目标一致，内容变更走代码发布。

## Migration Plan

新工程直接在当前空仓库落地，无既有系统需要迁移。发布方式为 `npm run build` 生成 `dist/` 静态目录，部署到任意静态托管即可；回滚只需重新发布上一版 `dist/`。
